# Architecture and next milestones

Spring Boot creates incidents and outbox JSON in the same PostgreSQL transaction. A separately scheduled Java publisher locks eligible rows, sends incident.created through Spring Kafka and records broker acknowledgement. A Dockerized Python worker validates events, records event-ID/hash receipts, retrieves five LangChain Documents through exact pgvector cosine search, saves content/source/score snapshots, and changes PENDING to RECEIVED atomically. Kafka offsets follow PostgreSQL durability. Exhausted failures and invalid records are quarantined durably; they require operator investigation/replay.

Flyway manages incidentiq_api; public.runbook_chunks and pgvector remain separate and preserved. V1 is the incident/diagnosis schema; V2 adds outbox/receipts/failures and RECEIVED; V3 permits Kafka tombstones in failed-event storage; V4 adds runbook document/chunk indexing and retrieval snapshots. Delivery is at least once, with idempotent receipt handling. See event-delivery.md for operations.

Local all-MiniLM-L6-v2 embedding/indexing is implemented with an immutable model revision and offline runtime. Content hashes make ingestion idempotent. Future milestones: grounded generative LangChain analysis and diagnosis writes; incidents.analyzed events; live React views; richer processing metrics and Grafana dashboards. Legacy incidents.raw and incidents.analyzed topics remain intact. Kafka has one KRaft node and no failover. All runtime data and inference remain local; embedding inference is implemented, but generative diagnosis inference is not.
